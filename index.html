独立系テクニカルリスクレビュー · 監査前 · 本番前 · 改修

監査・本番・統合を止める技術リスクを、先に見つける。

park13 は、ブロックチェーン統合とデジタル資産インフラを、実際の使われ方に沿ってレビューします。重大なリスクを洗い出し、直す順番を付け、次の判断をはっきりさせます。渡すのは判定と実行可能な次の一手であり、監査バッジではありません。

00 · 経験

判断の両側にいた経験から

park13 の代表は James Dunn（シニア EVM インフラエンジニア）です。グローバルに規制されたデジタル資産事業の中で、本番ブロックチェーンの設計・統合・運用に携わってきました。あわせて、日本とオーストラリアの小規模事業で、自らの資本と納期と評判を賭けてオンチェーンプロダクトを立ち上げてきました。

機関側のシステムには、統制・追跡可能性・運用の規律が要ります。創業者側のローンチには、速度と優先順位の切り方、結果の引き受けが要ります。どちらも同じ問いに使います。このシステムは、どんな条件なら出してよいか。

01 · レビュー

同じレビューを、三つの判断に使う。

先に決めるのは、対象システム、想定する使い方、期限です。そのうえで、何が壊れうるか、何が判定を動かすか、次に何をするかを書きます。

00

監査前レビュー

本監査の前に、設計・実装・運用上の危険箇所と「先に直す / 監査会社に残す」を分けます。証明書は専門ファームが出します。

01

Go / No-Go

指定した X が、想定用途と運用条件のもとでリリース・統合・承認してよいかを判定します。

02

監査後の残存リスク

未解決の所見と実装差分を、宙に浮いた課題ではなく、実行可能なリリース判断にします。

任意：所見に付した ID のみ、改修または再検証（上限付き）。監査の合格は保証しません。

02 · 対象

コントラクトと、その周りで失敗するもの。

00

アーキテクチャと信頼境界

署名者、管理者、ベンダー、オラクル、ブリッジ、アップグレード経路。

01

カストディと取引フロー

アドレス管理、署名、確認、リトライ、停止、復旧。

02

コントラクトと統合ロジック

状態遷移、トークン挙動、イベント前提、ノンスと手数料。

03

ノード・RPC・依存関係

可用性、フェイルオーバー、プロバイダ集中、チェーン固有の挙動。

04

台帳と照合

オンチェーンと内部台帳の整合、例外、手動介入、証跡。

05

監視とインシデント対応

サイレント障害、誤検知、停止条件、復旧、エスカレーション。

範囲は、指定した一つの統合またはデジタル資産システム X の技術境界に従います。アクセスは、その判断に必要な範囲に限ります。

03 · 成果物

レポートの終点は、脆弱性一覧ではなく判断です。

  • 判定：想定用途に対する GREEN / AMBER / RED
  • 範囲：見たもの、見ていないもの
  • 優先順位付き所見：何が失敗し、どの程度か、誰が損をするか
  • 信頼境界：鍵、管理者、アップグレード、カストディ、ブリッジ、外部依存
  • 切り分け：監査前・本番前に直すもの / 監査会社に残す・後回しにできるもの
  • 判定を動かす条件
  • 経営向け要約：英語または日本語

例 · 「settlement bridge v2」 · 判定 AMBER · P13-04 と P13-07 はローンチ前に修正 · 残所見は計画済み

park13 のレポートは、正式なセキュリティ監査でも、規制上の保証でも、脆弱性がないことの証明でもありません。

04 · 進め方

狭く入り、判断し、見つかったものだけ直す。

01

範囲を固定する

X、必要な判断、期限、アクセスを決めます。固定価格は範囲に従います。

02

レビュー

資料・コード・運用の根拠を、想定用途に照らして見ます。質問は担当者に直接します。

03

判定とレポート

判断、優先所見、切り分け、日英いずれかの経営向け要約を渡します。

04

改修と再検証

任意・上限付き。書面の所見 ID に限ります。

05 · 適合

対象システムと、必要な判断が言える案件に限ります。

適合する案件

  • 期限のある監査・リリース・統合・承認・提携の判断がある
  • レビュー対象のシステム X（または統合経路）を特定できる
  • コード・技術資料・担当者に、合意した範囲でアクセスできる
  • リスクに応じて設計や実装を変える意思がある

提供しないもの

  • 「park13 レビュー済み」バッジや、正式な監査証明のみを目的とした契約
  • 期限のない常駐・スタッフ増強
  • トークン / NFT / 投資 / 上場 / 市場戦略
  • X も判断も特定しない一般論の助言

書面の所見 ID に限定した改修・再検証は、別見積もりのオプションです。

park13 はファームではなく、一人の実務です。同時に進める案件は限られるため、待ちが出ることがあります。

06 · 連絡

まず、レビュー対象 X を決める。

対象システム、必要な判断（監査前 / リリース / 統合など）、期限を送ってください。適合すれば、範囲・必要資料・固定価格を返します。バッジや本監査証明書だけが必要なら、専門ファームを案内します。
