監査や本番投入の前に、危険なところを洗い出し、先に直す。

指定したシステム（X）を、想定する使い方に沿ってレビューします。判定と優先順位付きの所見を出し、監査・リリース・統合の判断材料にします。正式な監査証明は出しません。必要なら、書面の所見IDに限って改修または再検証も行います。

00 · レビュー

同じレビューを、三つの判断に使う。

00

監査前レビュー

本監査の前に、設計・運用上の危険箇所と「監査前に直す / 監査会社に残す」を分けます。証明書は専門ファームが出します。

01

Go / No-Go

指定した X が、想定用途と運用条件のもとでリリース・統合してよいかを判定します。

02

監査後の残存リスク

既存の監査所見と実装差分を、残すリスクと次の手に整理します。

任意：所見に付した ID のみ、改修伴走または再検証（上限付き）。監査の合格は保証しません。

01 · 対象範囲

コントラクトだけでなく、その周りで失敗するものを見る。

00

アーキテクチャと信頼境界

署名者、管理者、ベンダー、オラクル、ブリッジ、アップグレード経路。

01

カストディと取引フロー

アドレス管理、署名、確認、リトライ、停止、復旧。

02

コントラクトと統合ロジック

状態遷移、トークン挙動、イベント前提、ノンスと手数料。

03

ノード・RPC・依存関係

可用性、フェイルオーバー、プロバイダ集中、チェーン固有の挙動。

04

台帳と照合

オンチェーンと内部台帳の整合、例外、手動介入、証跡。

05

監視とインシデント対応

サイレント障害、誤検知、停止条件、復旧、エスカレーション。

範囲は、指定した一つの統合またはデジタル資産システム X の技術境界に従います。アクセスは、その判断に必要な範囲に限ります。

02 · 適合条件

対象システムと、必要な判断が言える案件に限ります。

適合する案件

  • 期限のある監査・リリース・統合・承認・提携の判断がある
  • レビュー対象のシステム X（または統合経路）を特定できる
  • コード・技術資料・担当者に、合意した範囲でアクセスできる
  • リスクに応じて設計や実装を変える意思がある

提供しないもの

  • 「park13 レビュー済み」バッジや、正式な監査証明のみを目的とした契約
  • 期限のない常駐・スタッフ増強
  • トークン / NFT / 投資 / 上場 / 市場戦略
  • X も判断も特定しない一般論の助言

書面の所見 ID に限定した改修・再検証は、別見積もりのオプションです。

park13 はファームではありません。シニアの EVM / インフラ実務者が、一人でレビューします。所見とエグゼクティブ要約は、日英で渡せます。

03 · 連絡

まず、レビュー対象 X を決める。

対象システム、必要な判断（監査前 / リリース / 統合など）、期限を送ってください。適合すれば、範囲・必要資料・固定価格を返します。バッジや本監査証明書だけが必要なら、専門ファームを案内します。
